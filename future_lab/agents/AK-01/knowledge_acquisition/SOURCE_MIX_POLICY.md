# AK-01 — Source Mix Policy

## Purpose
Prevent a professional knowledge area from being supported by a single source class.

## Foundational knowledge
Preferred mix:
- authoritative body of knowledge / standard / canonical textbook
- scholarly book or high-quality synthesis
- primary sources where concepts originate or remain contested

## Algorithm / method
Preferred mix:
- original paper or authoritative derivation when relevant
- textbook/monograph explanation
- independent comparative or benchmark evidence
- implementation/reference documentation
- failure/limitation examples

## Fast-moving technology
Preferred mix:
- current official documentation
- release notes/specifications
- authoritative engineering references
- reproducible benchmark/case evidence
- security advisories where relevant

## Security knowledge
Preferred mix:
- standards/frameworks
- vulnerability/weakness taxonomies
- vendor/CERT advisories
- primary technical analysis
- real incident/failure cases

## Regulation / legal
Preferred mix:
- primary law/regulation
- official regulator guidance
- court/official interpretation when relevant
- secondary commentary only as supporting explanation

## Professional practice
Preferred mix:
- professional framework
- authoritative textbook/reference
- production case studies
- failure/postmortem evidence
- qualification tasks/tests

## Rule
Critical knowledge cannot be accepted from a homogeneous source set when independent corroboration is reasonably available.
