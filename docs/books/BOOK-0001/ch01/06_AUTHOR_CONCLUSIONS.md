# Chapter 1 — Author Conclusions

1. A useful LLM prototype can be easy to build, but many real use cases require stronger accuracy and reliability guarantees.
2. Understanding how LLMs are built helps diagnose failure modes even if the practitioner never trains a foundation model.
3. Model choice should be deliberate and evaluated against the use case, including cost constraints.
4. Fine-tuning is conditional, not automatic.
5. Hallucination/reasoning, latency/cost, external tools and RAG quality are separate production concerns.
6. Alignment/refusal training alone is a weak security layer against adversarial prompting.
