03 / ЧТО ВИДИТ АНАЛИТИК

Риски входят в общий список работ

Элементы оригинальной схемы

Владелец продукта добавляет и упорядочивает задачи. Общий список содержит функции и риски. Команда берёт работу из списка и создаёт систему.

Ключевая связь — обратная стрелка

Команда выявляет технические риски и возвращает их в общий список. Это обратная связь: анализ рисков продолжается после начала реализации.

К чему привязано в FATHER

К планированию аналитического кейса и проверке гипотез. Проблемы качества источников должны становиться задачами проверки, а не теряться в комментариях.

Первые два пункта — пересказ рисунка 3.6 и текста страницы 57. Применение в FATHER ниже — наше предложение, его нет в книге.
04 / ДЛЯ КАКИХ АГЕНТОВ

Предлагаемое распределение ролей

Аналитик

Выделяет идею и формулирует проверяемый риск: например, вывод основан на единственном источнике.

Socrates

Ищет контрпример, зависимые источники и альтернативное объяснение. Возвращает нерешённый риск в очередь.

Планировщик FATHER

Предлагаемая роль: ставит проверки рядом с задачами сбора; учитывает влияние риска на результат.

Knowledge Curator

Предлагаемая роль: сохраняет происхождение и статус проверки. Перед продвижением требуется решение человека.

Это карта применения, а не подтверждение, что все перечисленные агенты уже реализованы.
05 / КАК ПРИМЕНИТЬ

Один конкретный эксперимент

Ситуация: Алина предлагает архитектурное решение по одной книге. Риск — принять мнение автора за доказанную пригодность для FATHER.

Идея из книги → риск «нет независимой проверки» → задача на контрпример и альтернативу → оценка результата → решение человека

Критерий успеха: у предложения есть страница-источник, отдельная проверка, альтернатива и зафиксированное решение. Без решения объект не должен попадать в утверждённую KB.

Что может быть лучше: явная очередь рисков делает незакрытые проверки видимыми. Улучшение качества ещё нужно подтвердить экспериментом; цифры ускорения не заявляются.
