# Как применять знания книг на практике в 2026 году

Это **план практической инженерной работы**, а не утверждение, что весь проект уже построен. Технологии ниже — кандидаты; окончательный выбор зависит от требований, доступности, лицензий и измерений.

## Сквозной проект: внутренний помощник по техническим документам FATHER

**Заказчик:** инженер хочет спрашивать «Какие параметры влияют на VRAM модели?» и получать ответ из проверенных документов со ссылками на конкретные фрагменты.

**Успех:** на наборе заранее подготовленных вопросов система находит нужный источник, не подменяет неизвестные факты выдумкой, не выдаёт чужие данные и отвечает с измеримой задержкой.

### Уровень A — работающий учебный прототип без облака

1. Подготовить 5–10 разрешённых текстовых документов, указать идентификаторы источников.
2. На Python реализовать простейший локальный поиск (на первых шагах достаточно SQLite FTS5 или лексического поиска).
3. Принимать вопрос, выбирать релевантные фрагменты и показывать точную ссылку на источник.
4. Проверять отсутствие ответа при нехватке данных; не «достраивать» факты самостоятельно.
5. Создать независимые 20–30 вопросов с ожидаемым документом и ответом.
6. Сохранить результаты и ошибочные случаи в JSON/CSV.

**Не путать:** такой поиск ещё не полноценная генеративная RAG-система. Он доказывает только ingestion/retrieval/provenance.

### Уровень B — локальная LLM и RAG

Добавить генеративную модель с локальным inference runtime (например, llama.cpp/llama-cpp-python или совместимый OpenAI API сервер), embeddings, индекс (FAISS, Qdrant или PostgreSQL pgvector), reranker — только при измеримой необходимости.

**Важно:** при использовании внешнего API сначала проверять категорию данных, основания передачи, размещение, поставщиков и условия хранения. Никогда не отправлять конфиденциальные документы по умолчанию.

Проверки: retrieval recall@k, цитаты, groundedness, latency p95, стоимость CPU/GPU, неверные отказы, утечки, prompt injection.

### Уровень C — контролируемый агент

Ввести один инструмент с правом только чтения, явную схему аргументов, ограничение числа вызовов, журнал действий, RBAC. UAG решает, имеет ли агент право на конкретное действие. Недоверенный текст из книги или сети не является инструкцией к выполнению.

### Уровень D — подготовка специалистов ALINA

ALINA создаёт Knowledge Package и Learning Package; агент выполняет задания, POLYGON оценивает результат; после ошибок изменяются инструкции, workflow или база знаний. SFT/DPO/RL использовать отдельным экспериментом, если это обосновано данными.

### Уровень E — эксплуатация

Архитектор получает workload profile; измеряет p50/p95/p99, TTFT, tokens/s, память, перегрузку и стоимость. TIMA версионирует образ, конфигурацию, модель, промпты, индекс, тестовый набор. Canary/rollback включает все связанные версии.

## Технический выбор на 2026 год — решения, а не догмы

| Слой | Возможные инструменты | Что проверить до утверждения |
| --- | --- | --- |
| Python API | FastAPI | Версия, поддержка, тесты и нагрузка |
| Текстовые документы | Python + SQLite FTS5 | Полнота, качество извлечения, кодировка |
| Векторный поиск | FAISS / Qdrant / pgvector | Recall, обновления, ACL, производительность |
| Локальная модель | llama.cpp / llama-cpp-python | Лицензия модели, качество, VRAM, задержка |
| Контроллер / инструменты | Python функции + JSON Schema / MCP | Авторизация, timeout, запрет опасных операций |
| Запуск | Docker Compose, затем при необходимости Kubernetes | Ресурсы, сеть, безопасность, стоимость эксплуатации |
| Наблюдаемость | OpenTelemetry, Prometheus, Grafana | Traces, метрики, хранение и секреты |
| Квалификация | pytest и зафиксированные eval-наборы | Отрицательные тесты и независимые доказательства |

## Честные статусы

- **PLANNED** — методика написана.
- **CODE_ADDED** — программные примеры опубликованы, но не доказаны испытанием.
- **TESTED** — сохранены результаты воспроизводимого запуска.
- **QUALIFIED** — независимый POLYGON подтвердил требуемые критерии.

Нет проверенных измерений → нет заявления о достижении SLO или производственной готовности.
