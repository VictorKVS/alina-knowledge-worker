# FATHER / ALINA — стандарт лабораторий для книжных проектов

**Дата принятия:** 2026-11-23. **Область:** все записи каталога LIB-0001…LIB-0039 и вновь добавляемые книги.

## Последовательность и разграничение статусов

1. Сначала изучать ВСЕ книги по первоисточникам; для каждой прочитанной главы писать самостоятельную программу. По непрочитанным книгам допускается только `PROVISIONAL_PLAN_SOURCE_NOT_REVIEWED`, не утверждение о содержании или структуре глав.
2. После изучения всех выбранных книг свести понятия в **один** ALINA Knowledge Core; дедупликация сохраняет ссылки на отдельные первоисточники.
3. После объединения запускать интеграционные испытания Agent Factory / ALINA / POLYGON. Подготовка и даже исполнение отдельной toy-лаборатории сами по себе не означают qualification.

Статусы:
- `PROVISIONAL_PLAN_SOURCE_NOT_REVIEWED`: гипотеза по названию/категории, первоисточник не изучен;
- `SOURCE_REVIEWED_DESIGNED`: страница/раздел сверены, программа разработана;
- `READY_TO_RUN`: присутствуют скрипты, датасеты, зависимости, ожидаемые результаты;
- `TESTED_PASS` / `TESTED_FAIL`: реальные исполняемые тесты и evidence;
- `QUALIFIED`: независимый POLYGON подтвердил заранее утверждённые критерии.

## Паспорт каждой лаборатории

- Laboratory ID: `<LIB-id>-CHxx-LABxx`; точные chapter ID — только после чтения оригинала;
- book/source ID, title, edition, source provenance, SHA256 (если вычислен) и страницы;
- точный тезис/алгоритм **автора** отдельно от гипотезы **FATHER**;
- задача, риск, входные данные (синтетические/лицензированные), эталон и baseline;
- учебные уровни 1–6: понимаю, считаю, воспроизвожу, проектирую, доказываю, эксплуатирую;
- вариант **A**: учебный детерминированный пример;
- вариант **B**: сравнительный эксперимент с альтернативами;
- вариант **C**: интеграционный режим в FATHER, права UAG и qualification POLYGON;
- команды, зависимости, версии, окружение, ограничения, бюджет и безопасный rollback;
- happy-path, boundary, negative, adversarial и regression тесты;
- метрики, preregistered acceptance gate, ошибки, evidence и ADR;
- независимая проверка, решение `PASS / FAIL / NOT_RUN`.

**Требования:** human commits; ADR; data/component/security/qualification contracts; provenance + SHA-256; signed releases; SBOM/build provenance; доступы UAG; запрет готовности без end-to-end доказательств.

## Варианты выполнения лабораторий

A — Python/ручной расчёт/синтетические данные (минимум инфраструктуры).
B — сравнение готовых алгоритмов, библиотек, GPT/API и локальной модели на одинаковых задачах.
C — реализация проверяемого сценария в конечной линии `ALINA → FATHER → UAG → POLYGON`; можно использовать готовый компонент вместо переписывания алгоритма.

**Ограничение:** сценарии взлома или опасные действия — только изолированные авторизованные учебные стенды; никакие реальные целевые системы.

## Артефакты лаборатории

`LAB_PROGRAM.md`, `fixtures/`, `reference_answers.json`, `tests/`, `runbook.md`, `metrics.json`, `evidence/`, `adr.md`, `qualification.json`. Отсутствующие файлы не считать созданными: в исходных паспортных программах запланированы будущие артефакты, не код или измерения.

## Дедупликация

`LIB-0001 ↔ BOOK-001`; `LIB-0003 ↔ BOOK-002`; `LIB-0004 ↔ BOOK-003` — **один источник**, не три повторные версии знания. Записи LIB остаются паспортами, canonical CHxx files живут в BOOK-проектах.

**Источники авторского содержания:** только прямо прочитанные оригиналы или явно помеченные вторичные конспекты. По одним названиям глав содержательные выводы не выдумывать.
