# BOOK-002 — Чек-листы качества обучения и датасетов

**Происхождение:** термины отбора, очистки, дедупликации, PII, decontamination и data mixtures — Suhas Pai, *Designing Large Language Model Applications*, глава 2, PDF стр. 92–167. Пункты допуска, формы evidence и ролевые процедуры — **наша проектная методология FATHER**.

## A. Требования до начала обработки данных

- [ ] Определена роль обучаемого специалиста и список навыков.
- [ ] Есть заранее утверждённые метрики качества и запреты.
- [ ] Описаны целевые и редкие сценарии, ошибки и отрицательные случаи.
- [ ] Есть baseline и альтернативы обучения весов.
- [ ] Установлены требования к размещению, бюджету, задержке и рискам.

**FAIL:** нет метрики, исходных требований или прав на работу с данными.

## B. Паспорт каждого источника

- [ ] Название, автор, год, редакция и ID.
- [ ] URL, локальный ID или физический источник.
- [ ] SHA-256 исходного файла.
- [ ] Тип источника: PRIMARY / SECONDARY / SYNTHETIC / USER_SUPPLIED.
- [ ] Условия использования, авторские права, ограничения публикации.
- [ ] Полнота документа и качество извлечения.
- [ ] Ссылки на страницы, главы и фрагменты.
- [ ] История исправлений и owner.

**FAIL:** источник нельзя воспроизвести либо права на требуемое использование не подтверждены.

## C. Обработка и очистка

- [ ] Сохранён оригинал, нормализация обратима или документирована.
- [ ] Удаление boilerplate проверено на выборке.
- [ ] Единицы измерения, таблицы и нормативные ссылки не потеряны.
- [ ] Определены язык и домен документа.
- [ ] Правила качества проверены на редких и профессиональных документах.
- [ ] Отчёт показывает все исключённые записи и причины.

**FAIL:** фильтр разрушает ключевые профессиональные фрагменты.

## D. Дедупликация

- [ ] Exact duplicates: нормализация + hash + сохранение всех source_id.
- [ ] Near duplicates: выборка, выбранная мера сходства, аудит ошибок.
- [ ] Semantic duplicates: отдельно, без автоматического удаления важных вариантов.
- [ ] Разные редакции, даты, правила и юридические документы не объединены без проверки.
- [ ] Повторяемость может быть намеренной: её влияние документировано.

**FAIL:** потеря provenance или случайное объединение юридически разных документов.

## E. Защита сведений

- [ ] Проверены PII и секреты.
- [ ] Основание обработки данных подтверждено для каждого контура.
- [ ] Контекстная идентификация не игнорируется.
- [ ] Обезличивание прошло проверку остаточного риска.
- [ ] Train, eval, holdout, logs и backups имеют свои права.
- [ ] Передача данных внешнему API не происходит автоматически.

**FAIL:** выявлены защищаемые сведения без разрешённого режима работы.

## F. Разбиение и экзамены

- [ ] Разделение train/validation/test/holdout зафиксировано.
- [ ] Split по исходным документам/семействам, а не случайный split смешанных chunks.
- [ ] Проверены exact и n-gram overlaps.
- [ ] По возможности проверены near/semantic/paraphrase overlaps.
- [ ] Gold answers POLYGON исключены из учебных материалов кандидата.
- [ ] Каждый потенциально загрязнённый тест отмечен и рассмотрен.

**FAIL:** тестовые ответы оказались в обучении и достоверность экзамена нарушена.

## G. Состав и качество корпуса

- [ ] Определены домены, языки, стили, редкие случаи, источники.
- [ ] Пропорции данных мотивированы задачей, не скопированы из чужой модели.
- [ ] Есть срезы ошибок и данных, которые могут усиливать смещения.
- [ ] Синтетические данные имеют origin и независимую валидацию.
- [ ] Учтено влияние повторных эпох и запоминания.
- [ ] Проверено качество на неизменной независимой выборке.

**FAIL:** изменение смеси снижает критические навыки или нарушает ограничения.

## H. План обучения весов (расширение на следующие главы)

- [ ] Обосновано, почему prompt/RAG/tools недостаточны.
- [ ] Версии модели, tokenizer, обучающего кода и зависимостей известны.
- [ ] Установлены seed, optimizer, LR, batch, epochs, trainable params.
- [ ] Есть расчёт памяти, времени и стоимости с допущениями.
- [ ] Есть воспроизводимое логирование и контрольные точки.
- [ ] Контроль регрессий и безопасности проходит независимо.
- [ ] Переход к RL/RLHF/DPO оправдан метриками и проверяемым сигналом.

**FAIL:** обучение запускается без baseline, stop conditions или независимой оценки.

## I. POLYGON и выпуск

- [ ] Показаны train logs и версия датасета.
- [ ] Holdout не использовался для настройки кандидата.
- [ ] Качество на ключевых срезах не ниже согласованных границ.
- [ ] Проверены критические действия и права инструментов.
- [ ] Сохранены результаты latency/VRAM/cost для реальной нагрузки.
- [ ] Подписаны решения владельцев; rollback продуман.
- [ ] Подготовлены hashes/provenance/SBOM там, где применимо.

**FAIL:** нет доказательств либо критический запрет нарушен.
