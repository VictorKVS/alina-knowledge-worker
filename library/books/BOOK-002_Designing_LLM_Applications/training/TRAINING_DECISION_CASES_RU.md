# BOOK-002 — Архитектурные кейсы: какую методику обучения выбирать

**Важно:** нижеследующие кейсы — примеры инженерных решений FATHER, **не утверждения автора главы 2**. Они связывают её фундаментальные идеи о данных с будущими главами 5–9 об адаптации, настройке и оценке.

| Ситуация | Гипотеза | Первый эксперимент | Типичная ошибка |
| --- | --- | --- | --- |
| Устаревшая техническая информация | Недостаток актуальных источников | Версии документов + retrieval | Дообучать ради замены RAG |
| Ошибки JSON | Проблема формата | Schema + constrained outputs | Сразу запускать LoRA |
| Слабое понимание инженерного домена | Недостаточные знания или адаптация | Frozen eval с RAG и SFT/PEFT альтернативами | Считать наличие PDF гарантией навыка |
| Плохая работа с инструментом | Неудачный контракт/API/права | Tool schema, deterministic validation, UAG | «Обучить модель быть безопасной» вместо enforcement |
| Ошибки в длительных последовательностях действий | Планирование и состояние | Workflow с валидацией и контролем ошибок | Предположить, что RL сам решит проблему |
| Регрессия после SFT | Изменение поведения | Срезы целевых и общих задач на holdout | Принять прирост только одной метрики |
| Высокий train score, плохой экзамен | Перетренированность или contamination | Аудит split, near duplicates, unseen tests | Увеличить эпохи без диагностики |
| Данные содержат ПДн | Недопустимая обработка или риск утечки | Legal/privacy gate, dataset isolation | Отправить их в облачный сервис по умолчанию |

## Пример решения архитектора

**Заказчик:** «Агент ALINA должен обучить специалиста по ИБ, который отвечает по техническим нормативам».

- Цель: ответы с точными доказательствами по актуальным документам.
- Способ №1: RAG по допущенным первоисточникам, ручная проверка ключевых ответов.
- Способ №2: SFT/LoRA на разрешённом наборе экспертных ответов, если baseline не достигает целевых метрик.
- Выбор: на одном frozen наборе сравнить качество, цитаты, стоимость, задержку и регрессии.
- Неприемлемо: смешать train и holdout, считать использование документов разрешённым без лицензии.

## Экзамен ALINA

Для каждого кейса агент должен выдать: диагноз → альтернативы → evidence → выбранный эксперимент → критерий завершения → что может пойти не так → кому эскалировать. Эталон проверяет не выбор модного метода, а доказуемость решения.
