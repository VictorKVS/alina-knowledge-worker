## 1. Как выбрать модель, а не бренд

Начинаем с функции агента: document extraction, source classification, graph synthesis, planning, code, report.

Фиксируем жёсткие критерии до сравнения: лицензия, конфиденциальность, предел стоимости, структурный формат, минимальная доля точных решений, критические ошибки, latency. Затем сравниваем GPT API, локальную LLM или другой разрешённый вариант **на одном наборе**.

`CandidateScore` не должен скрывать critical FAIL за высокой средней оценкой. Принцип автора (286–288): выбор по задачам, стоимости, времени генерации, лицензии, опыту и nonfunctional требованиям.

## 2. Base, Instruct, Chat

- **Base:** предобучение на последовательностях; не обязательно надёжно следует пользовательским инструкциям.
- **Instruction tuned:** дополнительное обучение на примерах инструкций/ответов, более прямое следование задачам.
- **Chat tuned:** вариант, ориентированный на диалог.
- **Long context:** поддержка большого окна не доказывает, что модель одинаково хорошо использует любой участок длинного входа.
- **Domain-adapted:** специализированная модель — кандидат для узкого задания, качество проверяется.

Книга предупреждает: дополнительная настройка может менять прежние способности, нельзя автоматически считать instruct всегда лучше base для любой задачи.

## 3. Оценка и противоречия benchmark

PDF 291–306: EleutherAI LM Evaluation Harness, MMLU, HELM, Elo comparisons, contamination. Универсальные лидерборды недостаточны. Пользовательская цель определяет собственные benchmark задачи и варианты негативных примеров.

Для ALINA: отдельные валидации 1) знания и цитаты, 2) выбор метода, 3) JSON contract, 4) tool safety, 5) регрессия, 6) затраты. Подтверждение фактов доверять не только LLM-судье. Сохранять человеко-проверяемое evidence и независимые испытания POLYGON.

## 4. GPU/память и запуск

PDF 307–311: float32, float16, BF16, int8/низкобитное представление, Hugging Face Accelerate, Ollama, APIs. Для первого проекта FATHER GPT в чате или через разрешённый API уменьшает стартовые инфраструктурные затраты; локальные модели остаются альтернативой. При этом храним данные в своей системе, обеспечиваем ограничение контекста и права передачи. Примеры SDK в книге могут быть устаревшими — использовать текущие проверенные API.

## 5. Декодирование: почему одинаковые запросы дают разные ответы

- **Greedy:** на каждом шаге максимальная вероятность.
- **Beam:** сохраняется несколько наиболее обещающих продолжений.
- **Top-k:** выбор из k наиболее вероятных токенов.
- **Top-p/nucleus:** динамический набор с заданной суммарной вероятностью.
- **Temperature:** перераспределяет вероятности. `temperature=0` не гарантирует полной повторяемости (PDF 318–319).

Пример: при распределении `[0.6, 0.3, 0.1]`, greedy выбирает первый; top-k=2 исключает третий; top-p=0.8 включает первые два. Этот пример математический, не вывод реальной модели.

## 6. Structured outputs — критически для ALINA

LLM может отвечать свободным текстом, но FATHER должен получать **машинные артефакты** по жёстким контрактам.

```json
{
  "agent_id": "OSINT-001",
  "source_id": "SRC-019",
  "decision": "NEW_VERSION",
  "evidence_refs": ["SRC-019#p7"],
  "requires_human_review": true
}
```

Схема проверяет структуру и допустимые значения, **но не истинность факта** и **не право на инструмент**. Для последних нужны provenance, алгоритмическая проверка, UAG и POLYGON. В книге (320–323) приведены JSON Schema, Jsonformer, regex и контекстно-свободные грамматики.

## 7. Что меняет этот урок в проектировании FATHER

Рабочий ALINA GPT-mode сначала получает спецификацию роли, ограниченные источники через RAG, JSON-контракты и набор тестов. Каждый новый агент имеет `model_selection_record`, версии Knowledge/Prompt/RAG/Learning Packages, `output_schema` и `eval_result`.

Поток: `requirements → ALINA design → baseline model evaluation → knowledge/prompt/RAG package → FATHER assembly → UAG → POLYGON → controlled change`.

## 8. Чек-лист архитектора

- [ ] Назначение агента, область ответственности и ограничения записаны
- [ ] Модели сравнены по конкретным задачам, не только leaderboard
- [ ] Разрешены лицензия, коммерческое использование, обработка данных
- [ ] Есть baseline, frozen eval и независимый holdout
- [ ] Выбран способ декодирования с измеренным поведением
- [ ] Валидация JSON отделена от проверки фактов и полномочий
- [ ] Источники и версии RAG фиксируются
- [ ] Промпты и форматы ответа версионируются
- [ ] Есть stop conditions, человек и rollback
