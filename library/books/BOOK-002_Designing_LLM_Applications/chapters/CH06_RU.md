## 1. Сначала критерий необходимости

Автор (PDF 329–331) описывает задачи, когда few-shot + расширение инструкций недостаточны: перенос грамматического времени и специальные финансовые тексты. Модель получает примеры входов и ожидаемых ответов и обновляет веса. Автор отдельно советует использовать RAG, если требуется в первую очередь добавить **новые или изменившиеся сведения**. Fine-tuning может ухудшать другие способности модели.

**FATHER-применение:** ALINA сначала проверяет качество базы, RAG, промпта и инструментов. Требование обучать модель появляется только при измеримом остаточном дефиците поведения и доказанном преимуществе fine-tuning над baseline.

## 2. Пример из книги

Автор обучает Llama2-7B классифицировать политические обещания: будущая фраза ещё не обязательно обещание; требуется конкретное, осуществимое действие под контролем субъекта (PDF 332–333). Результат моделируется как инструкция, фрагмент текста и целевой True/False. Для ALINA мы **не переносим политические категории**, а повторяем структуру задания для отслеживания версий документов и источников.

## 3. Что обновляется

`instruction + input → tokens → forward → loss → gradients → optimizer step → modified trainable weights`.

При RAG документ добавляется в контекст во время использования, а веса не меняются. При PEFT/LoRA меняется малая часть обучаемых параметров; полное обучение основных весов не обязательно.

## 4. Параметры, которые надо понимать

- `learning_rate`: шаг обновления; высокие значения могут разрушать полезные параметры
- `optimizer`: AdamW, Adafactor и альтернативы; AdamW требует дополнительной памяти для состояний
- `scheduler`: constant, warmup, cosine, linear и др.
- `gradient_checkpointing`: меньше памяти, но повторный расчёт активаций
- `gradient_accumulation`: накопление градиентов нескольких micro-batches; не сокращает общую арифметическую работу
- `label_smoothing`: регуляризация меток и возможная калибровка
- `NEFTune`: шум в embeddings **во время обучения**, требует проверки регрессий
- `batch_size`: компромисс по памяти, скорости и оптимизации
- `LoRA`: параметроэффективное обучение; реальная пригодность зависит от задачи и инфраструктуры

Автор использует конкретные настройки в демонстрации (в том числе LR=3e-4, cosine, warmup 0.03, LoRA), но **не считать их универсальными параметрами для FATHER**. Код с зафиксированными версиями библиотек из книги 2025 года требует актуализации до запуска.

## 5. Как делать датасет

PDF 360–364: структура примера — `instruction`, необязательный `input`, `output`; обучение может быть single-task или multi-task.

Варианты автора:
1. Использовать проверенный существующий instruction dataset (с учётом условий лицензии).
2. Преобразовать размеченные task datasets в инструкции по шаблонам.
3. Подготовить качественные ручные seed cases и дополнить синтетическими примерами, созданными LLM.

**Super-NaturalInstructions** включает цель, положительные и отрицательные примеры, ограничения и объяснения ошибок.

**Self-Instruct** генерирует разнообразные задания на основе seed; **output-first** полезен для контроля баланса меток; **Evol-Instruct** усложняет условия и расширяет тематику с фильтрацией кандидатов.

В PDF 373 книга содержит предупреждение о применении выходов OpenAI при обучении конкурирующих моделей. Это отражает формулировку периода написания книги; перед актуальным коммерческим применением требуется сверить действующие условия соответствующей услуги и законодательства.

## 6. Наш контракт ALINA: dataset record

```json
{
  "case_id": "DOC-EX-0001",
  "source_id": "SRC-1",
  "source_version": "v1",
  "instruction": "Классифицируй связь двух документов",
  "input": {"document_id": "D2", "previous_id": "D1"},
  "expected_output": {"decision": "NEW_VERSION"},
  "label_origin": "HUMAN_VERIFIED",
  "evidence_refs": ["SRC-1#p3"],
  "split": "train",
  "qualification_status": "NOT_RUN"
}
```

**Особенности:** убирать PII и запрещённые данные, отделять обучение и holdout по документам и семействам источников, хранить исходный hash/provenance, не считать GPT-сгенерированный ответ автоматически эталоном. Права на исходники проверять отдельно.

## 7. Acceptance criteria перед запуском fine-tuning

- Есть замороженный baseline той же модели с тем же набором задач.
- Есть правомерный и качественно размеченный dataset.
- Train/validation/holdout не имеют перекрёстных дубликатов и версий одного источника.
- Есть воспроизводимый config и ресурсы.
- Сравниваются качество, калибровка, регрессия, скорость и стоимость.
- Независимый POLYGON разрешает выпуск только после проверок.
