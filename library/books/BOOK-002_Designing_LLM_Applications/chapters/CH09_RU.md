## 1. Чего хотим от оптимизации

Сократить число вычислений, ускорить вывод токенов, снизить память для параметров и активаций. Отдельно проверять влияние на **качество**, ведь ускорение с неприемлемыми ошибками бесполезно.

В autoregressive decoder каждый следующий токен зависит от предыдущих, создавая последовательный bottleneck. Сложность обычного attention зависит от контекста; конкретные варианты механизмов и оптимизаций нужно сравнивать отдельно.

## 2. KV-cache

Кэшируются ключи и значения уже обработанной части последовательности, чтобы не перерасчитывать их снова. В книге (462–466) рассматриваются повторяющиеся системные промпты и документация. Cache хранит дополнительные данные: memory/time tradeoff. Внешние сервисы могут тарифицировать кеширование отдельно — цены/TTL из книги отражают время её выхода и требуют актуальной проверки.

**FATHER:** cache key учитывает tenant, модель, tokenizer, template, политику доступа, source hash/version, параметры; никакого переиспользования между несогласованными trust zones.

## 3. Early exit

При sequence early-exit завершаем обработку на промежуточном слое для всего входа, при token-level — отдельно для токенов. Автор обсуждает CALM и FastBERT (466–472). Потенциальное ускорение сопровождается риском снижения качества; не каждый inference runtime умеет такие механизмы.

## 4. Distillation

Teacher → student, этапы: подготовка данных + обучение. Сигналы: наблюдаемые тексты, дополненные примеры, logits, внутренние представления, teacher feedback. В книге также weak-to-strong generalization (472–479). Дистилляция подвержена catastrophic forgetting, важно независимое сравнение.

Не считать ответы GPT автоматически разрешёнными для обучения альтернативной модели: перед использованием проверять применимые условия соответствующей услуги и права на данные.

## 5. Speculative and parallel decoding

Speculative: небольшая draft-модель предлагает несколько токенов, target-модель проверяет; важно измерять acceptance rate и фактический speedup (480–482). Parallel generation требует независимости частей результата; согласованность финального текста проверять. Medusa использует дополнительные decoding heads (482–484).

## 6. Quantization

FP32 ~4 байта/параметр, FP16/BF16 ~2 байта/параметр, INT8 ~1 байт/параметр; 4-bit ~0.5 байта/параметр в идеальной оценке. Это **только весовая память**, не полная VRAM; overhead и KV-cache учитываются отдельно.

Симметричная схема отображает ноль в ноль; асимметричная допускает смещение zero-point. Данные с выбросами ухудшают точность квантования. Для активаций отличать static и dynamic calibration (PDF 485–490).
