# ALINA — учебная программа Knowledge Steward / Curriculum Engineer

Цель: принимать разрешённые источники, понимать документ, выявлять повторы и противоречия, хранить прослеживаемые факты, формировать учебные программы и передавать знания агентам.

| Модуль | Чему научиться | Практический артефакт |
|---|---|---|
| A01 — Источники и происхождение | Составляет паспорт документа, его права, редакцию, URL, дату, hash и точные ссылки | source manifest |
| A02 — Извлечение документов | Находит таблицы, заголовки, формулы, страницы; оценивает пропуски | parsed document + spans |
| A03 — Качество информации | Выявляет мусор, ошибки OCR, неподходящий язык и потери смысла | quality report |
| A04 — Дедупликация | Различает одинаковые файлы, текстовые копии, близкие документы и изменения редакции | duplicate decision report |
| A05 — Источниковая независимость OSINT | Прослеживает цепочки перепечаток и отделяет независимое подтверждение от репоста | claim provenance cluster |
| A06 — Защита данных | Проверяет PII, секреты, допустимые цели хранения и обучения | permission matrix |
| A07 — Построение графа | Отделяет факт, мнение, метод, алгоритм, гипотезу и противоречие | typed nodes and relations |
| A08 — Учебная программа | Строит маршрут обучения, словарь, определения, эталоны, не раскрывая holdout | learning package |
| A09 — Ролевые компетенции | Даёт OSINT и Document Agent ограниченные представления общего графа | role view |
| A10 — Изменения и квалификация | Сохраняет версии, назначает регрессию, требует независимый POLYGON | changelog + qualification plan |

## Алгоритм ALINA на каждую единицу информации

```text
SOURCE -> RIGHTS/SECURITY GATE -> EXTRACTION -> QUALITY
       -> DUPLICATE/VERSION REVIEW -> CLAIM & PROVENANCE GRAPH
       -> KNOWLEDGE/RAG/TRAIN POLICY -> ROLE VIEW -> TESTS
       -> INDEPENDENT POLYGON -> VERSIONED RELEASE
```

### Уровни обучения
**Первый курс:** определяет термины и вручную сравнивает пять документов.
**Практикант:** различает raw hash, text hash, near duplicates, редакции и разные доказательства.
**Инженер:** создаёт автоматизированные решения с ручной проверкой спорных случаев, пишет tests.
**Эксперт:** оценивает ошибки ложного слияния и пропуска, права, стоимость, результаты экзаменов.

**Предлагаемые веса оценки:** provenance 25%, дедуп и редакции 25%, безопасность 20%, структура 15%, воспроизводимость 15%. Порог 85/100 только как проектное предложение: POLYGON должен его утвердить и проверить закрытыми кейсами.

## Границы
Результат урока ≠ обновление весов LLM. Знания RAG, обучение поведения агента и SFT/RL — разные механизмы. Следующие главы BOOK-002 будут расширять программу после фактического чтения исходника.

## Задача ALINA
Для новой книги записать: кто автор и редакция; что именно утверждается; какое основание; что нового по сравнению с библиотекой; чему и какого агента учит; как доказать, что навык освоен.
