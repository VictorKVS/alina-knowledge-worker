# CH06 — практикум ALINA: dataset before model training

**Источник:** Suhas Pai BOOK-002, PDF 329–377. Практикум — FATHER-адаптация идей главы.

## Задание A: 24 проверяемых seed cases

Подготовить ровно 24 учебных случая для Document Analyst. Классы: `INGEST_NEW`, `LINK_DUPLICATE`, `NEW_VERSION`, `RELATED_VARIANT`, `REVIEW`, `QUARANTINE`, по 4 случая на класс. Синтетические ID, искусственные данные, без персональных сведений. Для каждого: вход, правильный выход, правило, evidence, отрицательное отличие, сложность, источник метки.

**Нельзя** подменять человеку верификацию метки: label_origin отдельно указывать GENERATED_UNVERIFIED, HUMAN_VERIFIED, RULE_VERIFIED.

## Задание B: controlled synthetic growth

Сформировать пять вариантов инструкции для каждого seed:
1. Paraphrase без изменения семантики;
2. Дополнительные ограничения;
3. Больше нерелевантных деталей;
4. Изменение структуры входа;
5. Отрицательный случай с минимальным отличием.

Проверить, что итоговые метки не изменились самовольно, а если изменились, создать отдельный ID и повторную разметку. Использовать output-first генерацию, если нарушается баланс классов.

## Задание C: isolation

Разделять наборы по source_family_id, а не по отдельным строкам: одна редакция, перепечатка, перевод и её парафраз не должны попасть одновременно в train и holdout. Заморозить hash и версию.

## Задание D: GPT vs fine-tuning gate

Сначала запускать без изменения весов:
- GPT + zero-shot prompt;
- GPT + few-shot examples;
- GPT + versioned RAG;
- GPT + structured output and deterministic checks.

Fine-tuning рассматривать только при устойчивой дефицитной точности в ограниченной задаче и наличии подтверждённой выгоды после оценки. Ни одна метрика заранее не объявляется доказанной.

## Задание E: абляция

Если запущен fine-tuning: фиксируем датасет и остальные настройки, проводим runs с компонентом и без него; оцениваем не только target task, но и иные навыки (regression). Это отдельно от проекта FATHER и не должно задерживать первое использование GPT.
