Источник: BOOK-002 PDF 378–413. **Это план эксперимента**, не отчёт о результатах.

## A. Анализ ошибки

Для OSINT Document Agent выбрать три типа ошибок:
1. устаревший факт или отсутствующая цитата;
2. неверное решение при правильных источниках;
3. неправильный формат или недопустимое действие инструмента.

Для каждого сохранить input, refs, expected, actual, severity, baseline_version.

## B. Сравнение подходов

| Возможное исправление | Когда пробовать первым | Нужны ли обновлённые веса |
|---|---|---|
| Обновить KB и RAG | отсутствующие/новые факты | нет |
| Поправить обычный prompt/JSON schema | формат, порядок работы | нет |
| Детерминированный код/инструмент | вычисления, версии, точное сопоставление | нет |
| Дополнительная модель-эксперт | сложная специализированная проверка | необязательно |
| SFT/LoRA/adapters | устойчивое ошибочное сопоставление вход-выход | да, обучаются адаптируемые параметры |
| DAPT/TAPT | серьёзное несоответствие модели языку/домену | да |

## C. Catastrophic forgetting study

Только при разрешённом обучении и доступном checkpoint: заморозить общие и доменные benchmark, сравнить baseline → обучение без replay → обучение с replay, провести несколько повторений. Проверить устойчивость и unrelated tasks. **Запрет** считать результат улучшенным по одной метрике без regression.

## D. Ensemble study without weight training

Сравнить GPT alone, GPT + обычная программная проверка, GPT + независимая вторая оценка. Зафиксировать критические ошибки и стоимость. Согласие нескольких моделей не является проверкой истины; независимая внешняя проверка обязательна.

## E. Qualification gate

Не выпускать новый checkpoint или адаптер без версии, лицензии, подтверждённого улучшения на holdout, отсутствия недопустимой регрессии и права отката.
