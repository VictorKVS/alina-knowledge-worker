# BOOK-002 / CH05 — Практикум для ALINA GPT Runtime

**Источник:** PDF 264–328; цели ALINA/FATHER и предложенные критерии — **наше инженерное расширение**.

## Лаборатория A. Выбор подходящей LLM

Создаём `candidate_matrix`: provider, exact_model_revision, base/instruct/chat, hosting, license and privacy, cost, TPOT, input budget, Russian quality, structured output quality, safety and citation accuracy. Все поля с непроверенной актуальностью — UNKNOWN.

Тест: 20 публичных учебных кейсов OSINT/document classification + отдельный закрытый набор POLYGON. Сравниваем одинаковые задачи по frozen gold. Ни одна модель не объявляется победителем по предварительной интуиции.

## Лаборатория B. Декодирование

Без внешних библиотек [toy code](../alina_kb/labs/ch05_decode.py) проверяет greedy, top-k, top-p на условном распределении. Реальные сравнения выполняются **отдельно** через модельное API с фиксацией точной версии, параметров и результатов.

## Лаборатория C. Структурный ответ ALINA

Зафиксировать `decision` как enum: INGEST_NEW, LINK_DUPLICATE, NEW_VERSION, RELATED_VARIANT, QUARANTINE, REJECT, REVIEW. Обязательно сохранять source_id, evidence_refs, needs_review. Не принимать решение только потому, что JSON валиден.

- Подготовить исходные метаданные.
- Отправить LLM инструкцию с форматом.
- Проверить JSON parser + schema.
- Проверить evidence и права вне модели.
- Критические UNKNOWN → REVIEW/QUARANTINE.
- Логировать ошибки и токены для сравнения вариантов.

## Лаборатория D. GPT как ALINA

Для одного будущего агента выбрать цель, сформировать Knowledge/Prompt/RAG/Learning/Qualification Packages с версиями и ссылками. Отдать FATHER на сборку только после человеческого просмотра. Если GPT ошибся, зафиксировать тип ошибки и выбрать **минимально нужное** изменение. Никаких заявлений об автономном ежедневном обучении без реальной автоматизации.
