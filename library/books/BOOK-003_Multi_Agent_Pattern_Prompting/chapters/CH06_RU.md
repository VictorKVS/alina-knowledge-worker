## Тщательный разбор
### 1. ETL integration patterns
Раздел демонстрирует конкретный ETL из источника документов в векторное хранилище на базе Airbyte и Pinecone; это практический пример, не требование использовать именно этих поставщиков.

### 2. Channel Adapter and Strategy
Автор выделяет Channel Adapter и Strategy как удобные способы унифицировать поступление данных из разных источников, смену connectors и механизм выполнения загрузки.

### 3. Airbyte connectors and configuration
Конфигурация через no-code или YAML должна быть версионированной и проверяемой. Состояние задания sync, факт успешной индексации и наличие корректных метаданных — разные проверки.

## Инженерный алгоритм: наша адаптация для FATHER
1. Проверить лицензию, доступность, регион и безопасность выбранных сервисов
2. Создать независимый контракт Source Adapter → Normalized Document
3. Провести тестовую загрузку ограниченного набора с known gold
4. Проверить число документов, метаданные, дубли и ошибки
5. Добавить incremental повтор, rollback и capture evidence

## Типовые ошибки и ограничения
- Не считать завершённый sync доказательством корректного retrieval.
- Не привязывать общие контракты FATHER к SDK одного вендора.
- Не отправлять персональные или коммерческие данные в сервис без согласованного режима обработки.

## Применение в FATHER / ALINA / FRODO / POLYGON
FATHER создаёт универсальный adapter API; Airbyte/Pinecone можно исследовать в лаборатории, а локальные компоненты выбирать по реальным условиям эксплуатации.
