# Практикум 2026 — от поиска документов к RAG-ассистенту

## Сценарий

У нас есть три текстовых справки. Студент задаёт вопрос о RAG или GPU. Программа должна найти подходящий документ и привести его **идентификатор**, а если информации нет — прямо сказать об этом.

### Практическое задание № 1: retrieval без LLM

На первом занятии не нужна GPU и внешняя сеть. Сначала докажем, что поиск работает.

[Рабочий пример на Python](../../labs/2026_document_search/search.py) · [Автоматические тесты](../../labs/2026_document_search/test_search.py)

В каталоге GitHub выполните:

```powershell
cd library/labs/2026_document_search
python -m unittest -v
python search.py "Что такое RAG?"
python search.py "Как определить KV cache?"
```

Ожидается список найденных источников с оценкой совпадения. Если вопрос вне учебного корпуса, программа должна вернуть «Источник не найден».

## Техническая модель

`question -> tokenize -> compare with allowed document snippets -> rank -> output source_id and text`

Это **лексический поиск**, не генеративная модель и не настоящая семантическая RAG. Такие базовые механизмы изучаем до подключения embeddings и LLM.

## Практическое задание № 2: переход к RAG

1. Загрузить документы в подготовленное хранилище.
2. Построить embeddings (например, FAISS/Qdrant/pgvector по результатам оценки).
3. На одном фиксированном наборе вопросов сравнить простой поиск и поиск embeddings по Recall@k.
4. Разрешить генерацию ответа LLM **только** на базе найденных фрагментов.
5. Проверить корректность цитат и ответы «недостаточно данных».
6. Провести негативные тесты: prompt injection внутри текста, попытка доступа к чужому документу, длинный запрос.

## Применение для System Architect в FATHER

Вход: задачи, data classification, набор источников, целевые метрики, ограничения по размещению.  
Выход: ADR по поиску/LLM/инструментам, схема потоков, контракт доступа, результаты тестов, оценка TCO.

## Применение для ALINA

ALINA создаёт карточки знаний с точным source_id, задания и эталоны. Проверяющий POLYGON не должен обучать агента на собственных контрольных ответах.

## Типичные ошибки первокурсника

- «Программа запустилась, значит AI-система готова» — нет, это только smoke test.
- «Релевантный документ гарантирует правильный ответ» — нет, нужен ответный контроль.
- «Можно загрузить любые PDF в GitHub» — нет, сначала проверка прав.
- «В 2026 году надо сразу Kubernetes» — нет, сложность инфраструктуры должна быть обоснована нагрузкой.

**Статус практикума:** учебная процедура и код добавлены; реальные тесты и benchmark ещё должны быть подтверждены evidence.
