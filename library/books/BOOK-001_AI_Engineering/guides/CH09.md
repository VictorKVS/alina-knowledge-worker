# BOOK-001 / Глава 9 — Inference Optimization

**Источник:** вторичный конспект книжного клуба, PDF страницы 46–50; оригинал полного текста недоступен. Этот материал — самостоятельное учебное пособие и инженерная интерпретация для FATHER, а не полный перевод.

## Цель
Обязательны фактический workload, latency budget, tokens/s, p95/p99, goodput, расход GPU/VRAM и профили нагрузки; требования заказчика задают gates.

## Словарь, определения и тезисы

### Inference server
Размещение модели, обработка запросов, управление ресурсами.

### Compute vs bandwidth bound
Проверка причины задержки по типу операции.

### Roofline
Сопоставление интенсивности вычислений и возможностей оборудования.

### Online vs batch
Компромисс задержки и стоимости.

### Metrics
TTFT, TPOT/ITL, latency percentiles, throughput, goodput.

### Accelerators
CPU/GPU, численная точность, память и энергетика.

### Model compression
Quantization, distillation, pruning с оценкой качества.

### Speculative and parallel decoding
Черновые токены, проверка и ограничение выигрыша.

### KV-cache and PagedAttention
Управление повторно используемыми ключами/значениями.

### Kernel optimization
Fusion, tiling, vectorization, compiler lowering.

### Service batching
Static, dynamic, continuous batching.

### Parallelism
Replica, tensor, pipeline, context, sequence; prefill/decode split.

### Prompt caching
Повторное использование префиксов с контролем безопасности и актуальности.

## Методы и процедуры

1. Декомпозиция latency: сеть → очередь → prefill/TTFT → decode/TPOT → инструменты → форматирование.

2. Capacity planning: traffic slices × tokens/request → измеренный throughput → требуемые реплики + headroom.

3. Поиск Pareto решений по p95/p99, goodput, расходам и quality gate при неизменной нагрузке.

## Логика аргументации, реконструкция по конспекту
Требуется снизить задержку и стоимость → найти bottleneck → различить модельные, аппаратные и сервисные методы → измерить trade-offs на реальном workload.

## Экзаменационные задания с эталонами

### BOOK001-CH09-L01: Определение узкого места
**Задача:** GPU занята на 100%, p95 высокий.

**Эталон:** Проверить MFU, MBU, очередь, TTFT/TPOT и профиль входов; загрузка GPU сама по себе недостаточна.

**Типовая ошибка:** Считать 100% GPU util доказательством эффективности.

### BOOK001-CH09-L02: KV-cache
**Задача:** Увеличили context и concurrent requests.

**Эталон:** Рассчитать KV-cache для архитектуры, batch и context; измерить peak VRAM.

**Типовая ошибка:** Использовать универсальный коэффициент 20%.

### BOOK001-CH09-L03: Continuous batching
**Задача:** Растёт очередь неодинаковых запросов.

**Эталон:** Провести эксперимент с continuous batching и оценить влияние на p95 и goodput.

**Типовая ошибка:** Обещать ускорение без нагрузочного теста.

### BOOK001-CH09-L04: Prompt cache
**Задача:** Кэшируется приватная персонализированная выдача.

**Эталон:** Сегментация по доступу, ключам контекста и актуальности, запрет опасного повторного использования.

**Типовая ошибка:** Общий кэш без изоляции пользователей.

### BOOK001-CH09-L05: OTUS 10k RPS
**Задача:** Заказчик требует 10 000 RPS и менее 200 мс.

**Эталон:** Уточнить p95 end-to-end vs TTFT, traffic mix, token lengths, тяжёлый async путь, сделать benchmark.

**Типовая ошибка:** Гарантировать на основании числа GPU.

### BOOK001-CH09-L06: Стратегии масштабирования
**Задача:** Предложены replica и tensor parallelism.

**Эталон:** Различить увеличение throughput через реплики и размещение модели на устройствах; сравнить стоимость.

**Типовая ошибка:** Утверждать, что обе стратегии эквивалентны.
