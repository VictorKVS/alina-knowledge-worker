# BOOK-001 — Глава 6. RAG and Agents

**Источник:** 55-страничный вторичный конспект Lean TECHniques, страницы PDF 32–37. Оригинал книги не проверен; изложение и инженерные примеры являются авторским учебным материалом FATHER.

## Задачи обучения
1. Различать retrieval, генерацию, граф знаний и обученные веса модели.
2. Объяснять BM25, dense, kNN, ANN, hybrid, reranking, query rewriting.
3. Обосновывать chunking с учётом целостности источников.
4. Проектировать работу агентных tools с проверкой полномочий и параметров.
5. Различать internal/short-term/long-term memory.
6. Оценивать поиск, инструменты и end-to-end выполнение.

## Раздел A. Поиск знаний
RAG собирает контекст из внешней памяти под конкретную задачу. Индексирование и запрос — самостоятельные операции. Терминологический поиск, embeddings и их гибрид необходимо сравнивать на документах и запросах заказчика. Большое число извлечённых фрагментов не гарантирует правильного ответа.

### Важные понятия
**BM25** — алгоритм лексического ранжирования; **dense retrieval** — семантический поиск по плотным векторам; **kNN** — точное извлечение ближайших векторов; **ANN** — приближённый поиск; **HNSW / IVF / PQ** — методы индексации/сжатия; **reranker** — повторное ранжирование; **hybrid** — комбинация методов.

### Практика FATHER (собственное применение)
По запросу «найди формулу sizing GPU в OTUS и объяснение у Chip Huyen» сначала определить разрешённый корпус, извлечь совпадения по имени, затем по смыслу, соединить/переранжировать результаты и вернуть два независимых указателя на источники. Ни один источник нельзя выдумывать.

## Раздел B. Подготовка контекста
Chunking, overlap, query rewriting, contextual retrieval и reranking помогают собирать информативный контекст. Для PDF с таблицами и формулами нужно сохранять структуру и ссылки на исходные страницы — это дополнение FATHER, а не заявленный в конспекте обязательный стандарт.

## Раздел C. Агент и инструменты
Агент воспринимает среду, строит план и выполняет операции инструментами. Большое число инструментов может усложнять выбор. Важны разделение планирования и исполнения, валидация плана, проверка допустимых функций и аргументов, оценка результата каждого шага, коррекция ошибок. Изменяющие действия требуют реального контроллера полномочий, а не только текста запрета.

## Раздел D. Память
В конспекте выделены внутренние знания весов, краткосрочный контекст и сохраняемая внешняя память. Для ALINA: RAG-корпус, каталог компетенций и журнал выполнения должны версионироваться отдельно; обновление базы не является fine-tuning. Суммаризация и слияние памяти требуют проверки потери фактов и конфликтов.

## Архитектурный контроль
System Architect получает требования Product / Business / System Analyst, сравнивает поиск по качеству, задержке, ресурсам и TCO, оформляет ADR. ALINA отвечает за evidence retrieval. CODEX внедряет контракты. TIMA измеряет эксплуатационные показатели. Security/UAG обеспечивают реальное разграничение действий. QA и POLYGON подтверждают работоспособность.
