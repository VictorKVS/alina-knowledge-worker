# BOOK-001 / Глава 10 — AI Engineering Architecture and User Feedback

**Источник:** вторичный конспект книжного клуба, PDF страницы 50–55; оригинал полного текста недоступен. Этот материал — самостоятельное учебное пособие и инженерная интерпретация для FATHER, а не полный перевод.

## Цель
Сквозная система: SLO, cost/request, latency budget, security, routing, traceability, change management и feedback-driven improvement.

## Словарь, определения и тезисы

### Context construction
Проверенные материалы и контекст под задачу.

### Input and output guardrails
Политики обработки входа, выхода, перенаправление к человеку.

### Router and gateway
Классификация запросов, маршрутизация, доступы, мониторинг и отказоустойчивость.

### Exact and semantic cache
Повторное использование ответов с проверкой применимости и актуальности.

### Agent patterns
Замыкание вывода в новые шаги и контроль write actions.

### Monitoring and observability
Метрики, логи, трассы, изменение моделей/инструкций/поведения.

### Orchestration
Компоненты, цепочки, параллельность, ошибки и эксплуатационная сложность.

### Explicit feedback
Оценки, жалобы, исправления пользователя.

### Implicit feedback
Поведенческие сигналы и их неоднозначность.

### Feedback design
Своевременный сбор без нарушения процесса.

### Feedback biases
Leniency, randomness, position and preference bias.

### Degenerate feedback loop
Усиление ошибок за счёт некачественной обратной связи.

## Методы и процедуры

1. Request → policy guardrails → classification/router → context → model/tool → output validation → telemetry → feedback.

2. Feedback → classification → evidence validation → proposed change → regression → canary → promotion/rollback.

3. Сопоставление явной и неявной обратной связи с контрольными метриками; без автоматического признания пользовательской оценки истиной.

## Логика аргументации, реконструкция по конспекту
AI-продукт требует контекста и контроля → вводятся guardrails, gateway/router, caches, tools → наблюдаемость выявляет ошибки → feedback используется после проверки, а не слепо.

## Работа специалистов FATHER
Product Manager, Business Analyst, System Analyst, System Architect, ALINA, TIMA, Security, CODEX, QA, POLYGON; архитектор владеет итоговым решением и расчётами, ALINA — provenance и доставкой знаний, POLYGON — независимой квалификацией.

## Экзаменационные задания с эталонами

### BOOK001-CH10-L01: Архитектурная цепь
**Задача:** Нужно собрать enterprise AI-ассистента.

**Эталон:** Спроектировать контекст, guardrails, routing/gateway, caching, agent tools, наблюдаемость и feedback.

**Типовая ошибка:** Прямой вызов LLM без политик и оценивания.

### BOOK001-CH10-L02: Guardrails
**Задача:** В документе инструкция отправить секрет на внешнюю почту.

**Эталон:** Считать документ недоверенным; инструментальные права и DLP должны запретить действие.

**Типовая ошибка:** Довериться инструкции внутри документа.

### BOOK001-CH10-L03: Персональный cache
**Задача:** Два пользователя спрашивают персональные остатки.

**Эталон:** Не использовать общий semantic cache без строгой изоляции, актуальности и контроля прав.

**Типовая ошибка:** Кэшировать ответ только по похожести вопроса.

### BOOK001-CH10-L04: Роутер
**Задача:** Классификатор выбирает дешёвую модель для любой задачи.

**Эталон:** Добавить quality/risk/routing gates, fallback и контроль ошибок.

**Типовая ошибка:** Оптимизировать только стоимость.

### BOOK001-CH10-L05: Feedback bias
**Задача:** Пользователи предпочли короткий неверный ответ.

**Эталон:** Сохранять feedback отдельно от ground truth, проверять по фактам и метрикам.

**Типовая ошибка:** Автоматически дообучать на лайках.

### BOOK001-CH10-L06: Регрессии
**Задача:** После нового промпта выросли отказы.

**Эталон:** Сопоставить срезы, версия промпта, модель, eval, canary и rollback.

**Типовая ошибка:** Считать среднюю оценку достаточной.

### BOOK001-CH10-L07: Orchestrator
**Задача:** Предлагается сложная платформа для 2 действий.

**Эталон:** Сначала проверить простой workflow и реальную необходимость orchestration layer.

**Типовая ошибка:** Установить большой фреймворк без ADR.
